## 1. Observed incompatibility

The baseline inspected is accepted commit
`c7eb7b3e4cad8f66d2098213998b7931474295a5`; its provenance sources are unchanged
from accepted occurrence commit `075f92fe9d6aa1afb0a16494769e9cc96ba0df16`.
These are three different content commitments, not interchangeable aliases:

| Content | Actual producer | Current representation |
| --- | --- | --- |
| Captured source tree | `services/scan/source_capture.py`, `_tree_evidence` | Length-framed relative paths and file contents; occurrence seal identifies `sha256-length-prefixed-path-and-content-v1` |
| Snapshot artifact collection | `services/snapshot/worker.py`, snapshot execution loop | SHA-256 over the fixed `SNAPSHOT_ARTIFACT_TYPES` order of present `artifact_type + ':' + artifact_body` pairs; status report calls it `snapshot_digest` |
| Fetched CPG archive bytes | `services/scan/detector_worker.py`, `run_detector_job` | SHA-256 of the fetched serialized CPG archive alone; the signed record also calls it `snapshot_digest` |

The last two differ in meaning despite the same field name. A digest string
does not identify its producer. Snapshot status is not itself evidence that
the detector signed that status digest. Source custody is not CPG identity.
Do not derive one value from another or claim that an old signature proves
a producer definition it never bound.

The baseline `canonical_record_bytes` enumerates dataclass fields. V1 excludes
only `record_schema_version` and `artifact_identity`; v2 includes all fields.
Adding another field to that class can therefore change both historical
signature inputs, even when its default is null. Existing v1 checksum tests
are frozen; existing v2 pipeline tests mostly construct and verify records
using the same current implementation, which alone cannot detect joint drift.

The old record JSON uses ASCII escapes and no final newline. The normalizer's
SARIF JSON uses literal UTF-8 and the full log ends in one LF. These encodings
must not be substituted for each other. The snapshot aggregate does not encode
member lengths and is not a raw manifest hash; independently verifying it needs
the exact original ordered member closure. A CPG storage suffix likewise does
not establish its archive format: the legacy serializer emits gzip/tar.

## 2. Compatibility decision

1. Preserve the existing v1 and v2 canonical bytes, explicit metadata, default
   version behavior and historical signature verification. Do not rewrite,
   relabel, upgrade, re-sign or delete old records to make them fit a new path.
   New validation must not silently invalidate previously valid history.
2. Freeze examples from the unchanged accepted implementation before extending
   its serializer. Expected bytes/checksums must not be regenerated by the
   implementation under test during ordinary tests. Record the actual capture
   commit, inputs and generator procedure. A static public key/signature may
   accompany a synthetic record; never retain a fixture private key.
3. New occurrence-finalization records require a distinct signed schema version
   with explicit content kinds and digest definitions. Do not add unsigned
   explanatory metadata to v1/v2 and then present it as signed producer evidence.
   The exact new version number, closed shape, codec and migration are a later
   coherent allocation after the producer map in §4 is closed.
4. Keep the legacy record class unchanged during the initial test-only phase.
   Any later shared serializer must use explicit version field sets or another
   mechanism proven by the frozen corpus to preserve old bytes exactly.
5. Existing graph/slice descriptor classes, statuses, namespaces and scoped
   conditional annotations remain independent. A new signed-record version
   does not upgrade artifact-identity versions, turn weak evidence strong,
   authorize suppression or certify source fidelity.
6. Existing legacy export shape stays compatible. A new complete export must
   carry the exact reconstructible signed payload plus its version/signature
   envelope and trusted public-key identification. Convenience projections are
   not substitutes for missing scope IDs or signed fields.
7. Dispatch every affected consumer by the actual record version. In particular,
   the existing `append_repartition_event` defaults its new child to v1 and must
   not receive a new-version record through implicit structural compatibility.
   Until a reviewed child-record path exists, unsupported versions must not be
   enabled in that workflow. This does not waive the final repartition promise.

## 4. Required producer map before allocating the final emitter

Each row needs an exact typed source, scope/equality checks, producer evidence,
failure semantics and falsifier tests. A configured string or injected protocol
is not the actual producer. Missing prerequisites stay visible, not fabricated.

| Required binding | Reusable source / unresolved work |
| --- | --- |
| Request/capture/run/occurrence/terminal attempt | Existing occurrence store retains these separately; add a bounded, authorized read joining the exact terminal result and policy, not the latest timestamp |
| Legacy scan/snapshot/Finding IDs | No durable occurrence-to-legacy mapping exists; define additive mappings and a truthful source-only oracle path without fabricated CPG rows |
| Source-tree identity | Actual verified capture receipt and sealed inventory/content bytes; retain the framed digest definition and immutable artifact reference |
| CPG archive and snapshot collection | Bind each actual available artifact separately; specify its exact raw/hash framing, ordered membership and producer. Explicit absence must not become successful core evidence |
| Precondition | Bind the actual `cw_detect` verdict artifact to this capture/analysis; `WorkerJob`'s default is not an observation |
| Spec/rule/model and authority | Use the accepted-content resolver/current reader and exact sealed content; do not equate `rule_id` and `spec_id` without actual producer semantics |
| Environment and code | Preserve detector environment, identity-attempt environment/code and complete observed environment as distinct commitments; an injected image digest is insufficient |
| Graph, slice and witness | Reuse R09 validation with actual attempt artifacts and retained witness bytes; distinguish witness raw hash from a semantic slice fingerprint |
| Eligible inventory and SARIF | Freeze a complete eligible inventory; preserve equal-byte duplicate occurrences, failed competitors and withheld raw evidence. Publish exactly the full-log bytes whose hash is signed |
| Persistent key and trust | Install an operator-controlled persistent local provider, historical public-key lookup and trusted key identification; ephemeral test keys do not fulfill this row |
| Finalization and publication | Stable operation/record IDs, immutable payload, transactional mapping and defined blob/signature/DB ordering; test replay, concurrent finalizers, stale fences and ambiguous commits |

The complete SARIF bytes must be fixed before their hash is signed. Do not
embed the resulting signature or record hash back into those same bytes and
create a circular commitment. Stable preallocated references may be used only
under an explicit deterministic-output contract; operational UUIDs must not
silently enter reproducibility comparisons.
